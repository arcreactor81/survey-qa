## 0. AMENDMENT — the durable Requirement Register (owner proposal, 2 Aug, GPT-reviewed: ACCEPT)

Owner: *"you take the survey doc, you create a table of sorts, and then the runs populate each row - if they miss something, it is visible immediately - and there you can flag other stuff too where needed."*

**Same judging algebra; NEW durable, reviewed coverage register.** Fable's initial framing to the owner ("orthogonal — contract judges cells, table is just the artifact") was WRONG and is corrected here: this changes the contract at the **lifecycle / data-authority layer**, though not at the matching layer. New authority chain:

`DocumentRevision → ExtractionCandidate → sealed ContractRevision → RunRecord/Observations → derived table cells`

The human-facing table is a **projection** of normalized records, never a mutable spreadsheet that scoring reads directly. Mapping: `ScopedRequirement` → parent row (counted once for extraction completeness); `facetInstance` → atomic score-bearing child row; `floorCase` → mandatory execution subrow; exploration observation → additional evidence inside a run cell (never denominator expansion); source-atom graph → provenance drawer + reverse source-coverage ledger; `assertionStatus` → row admission state; run observations → immutable case results aggregated into a visible cell.

**Where it grinds (must be handled):** TWO DENOMINATORS always reported separately — document requirements vs mandatory execution cases — never parent+children in one; a run cell is NOT scalar (the completed t1-easy run has 84 sessions under one column: cell carries coverage + verdict + pathConsistency + drill-down, never last-write-wins); `document-silent` / `explicit-negative` / `NOT_BROWSER_OBSERVABLE` / `blocked` / `not-reached` stay distinct explicit cell values (never blanks, and never `N/A` overloading them); ambiguous/disputed rows visible but withheld from pass/fail; every run references ONE immutable `contractRevisionId`+hash and may not regenerate its own denominator.

**Extraction completeness — review alone is NOT sufficient** (a reviewer cannot see a row that was never proposed). Required mechanism: (1) TWO independent extraction passes — whole-document/global-rule first, then source-block/table-aware with an explicit construct checklist; (2) a SOURCE-FIRST LEDGER classifying every paragraph, table cell (with inherited headers), footnote and cross-reference as normative / mapped-context / non-normative / ambiguous / unresolved; (3) a typed diff surfacing extractor-only requirements, scope-quantifier disagreements, duplicates, unmapped normative blocks, inventions; (4) human review focused on global rules, all/each/only/except quantifiers, termination+routing, cross-references, table-composed facts, ambiguities, extractor disagreements, then an independent omission challenge. Approval gates: zero unexplained normative blocks, all construct classes dispositioned, all scoped expansions previewed, no unresolved high-risk disagreement. Outcome is **adjudicated document coverage**, NOT guaranteed semantic completeness.

**Row identity/stability:** `requirementLineageId` (opaque, minted at first approval, survives revisions) + `requirementVersionId` (immutable snapshot) + `semanticFingerprint` (canonical typed expectation+scope+quantifier+exceptions). NEVER derive durable identity from Q-number, row position, quote, DOM locator, or content hash alone. Rewording/renumbering with unchanged meaning → same lineage, new version, same fingerprint. Threshold/destination/option-set/scope/exception change → same lineage, new version+fingerprint, old cells NOT reinterpreted. Repurposed question → new lineage. Split/merge → new lineages with splitFrom/mergedFrom. Removed rows stay visible as retired. Re-extraction may suggest mappings but only exact semantic equality carries forward automatically. A result cell binds `runId + contractRevisionId + caseVersionId + targetBuildId + resultPolicyVersion`; history is append-only; newly discovered requirements show `not-in-contract` for old runs unless an explicitly labelled retrospective adjudication is supported by existing evidence.

**Review ergonomics** (148 flat rows is not honestly reviewable): hierarchy = global/cross-cutting pinned first → sections/questions in document order → facet subrows → mandatory floor-case expansions → separate ambiguous / disputed / non-browser / proposed-row sections. Collapsed parents must show counts and unresolved states; collapsing may never hide incompleteness or enable bulk-green approval. Add a risk queue ordered by blast-radius × control-flow impact × uncertainty. Run history: current + one baseline by default, older runs behind a column picker; every column exposes document/contract version, target build, device/locale/config, result-policy version.

**This CLOSES the §7 oracle-gap fork** — recommendation adopted: source-verified unmatched claim → `ContractGapCandidate`, neutral for precision but BLOCKS final certification while pending; accepted → mint a row in ContractRevision vNext + explicit rescore/rerun; rejected or unsupported → FP; ambiguous → reporting-only; duplicate → link to existing row. Current denominator and historical scores never mutate silently; preserve both as-run and re-adjudicated results. "Flag other stuff" splits into FOUR LANES: document-backed contract gap (the only one that can become a row), taxonomy gap, ambiguity, unsupported site anomaly. Strict-immediate-FP is no longer defensible for a source-proven omission.

**Four corrections to Fable's framing:** (a) columns make cross-run repeatability visible but NOT path dependence "for free" — pass-on-one-route/fail-on-another *within* a run needs a mixed cell + route-level drill-down, aggregate stays fail-if-any; (b) the table is the primary AUDIT BODY, not the entire report — keep findings-first summary, partial-run warning, cost/coverage summary, evidence narrative; (c) `NOT_BROWSER_OBSERVABLE` requires a reviewed reason + alternative test surface where applicable, and must not become an escape hatch for blocked execution; (d) human edits must never make the table a second source of truth — every accepted row needs document provenance; undocumented vendor oddities remain unscored observations. Real-vendor fragility: build drift, personalization, locale/device variance, virtualized option lists, mid-run deploys ⇒ each run column needs a coherent target/config identity, mixed-build runs are INVALID, absence claims valid only with a complete scope-attested inventory.

**RESOLVED BY OWNER (2 Aug 2026) — supersedes the fork below.** Verbatim: *"we deploy this functionality from day one - use grok + deepseek to take passes/run extraction, and then create the list - and then ask someone to review it - phased rollout is of no use to us really in this case."* So the extraction pipeline ships COMPLETE from the start, not phased: **two independent extraction passes (Grok + DeepSeek, different provider families) → merged requirement list → human review before the run.** GPT's "review mandatory for P1/gold, automated-with-pause-on-risk for routine" recommendation is OVERRULED — review is in the product from day one.
Design note carried into implementation: the value of two passes is DISAGREEMENT DETECTION, not averaged quality, so the two passes must differ in METHOD as well as model (per §3 A1: one whole-document/global-rule pass, one source-block/table-aware pass with an explicit construct checklist) — two models running the same prompt produce correlated misses and would not have caught the global-compulsoriness omission that motivated this. Measurement caveat to resolve in P1: our extraction bakeoff measured gpt-oss-120b as the only model producing a complete contract, and did NOT test Grok on extraction; Grok's extraction quality is therefore unmeasured. Owner's choice is about provider independence, which is the right axis for cross-checking — but per-model extraction recall must still be measured, and the merge/diff step must surface each pass's misses rather than silently unioning them.

**SUPERSEDED FORK (kept for the record):** is human review required for EVERY live survey run, or reserved for audit-grade/high-risk cases? Mandatory-always contradicts the team's "hand over link + document, come back for the report" mandate — it makes the product *assisted* rather than hands-off. GPT recommends: review mandatory for P1, corpus/gold creation, and audit-grade mode; for default live operation use automated dual extraction and pause only on high-risk ambiguity or unresolved coverage gaps.

## 1. Settled core (both designs agree)

`confirmed typed document fact + verified typed site observation → scorer-derived delta → exact Boolean match`

- The document is the sole normative authority; a doc/site divergence is a site defect; `document-live-disagreement` is REMOVED.
- Human prose, severity, confidence, rationale, suspected cause: ZERO matching weight.
- NO lexical fallback, similarity score, threshold, margin, Hungarian assignment, or "near match" anywhere in defect credit.
- Negative claims require complete scoped evidence; partial observation = `unknown`, never "absent".
- Closed, public, versioned claim-kind registry with discriminated schemas; kind-specific canonical normalization; aliases cannot rescue incompatible facts.
- One oracle defect → at most one TP; exact duplicates don't inflate recall; contradictory alternatives are FPs.
- Attestation proves provenance, not truth; observation verification is a separate gate.
- RunRecord / OracleRecord / Scorecard / matcher all break to 2.0.0; v1 records reproduce only via frozen v1 tooling, never silently upgraded.

## 2. Reconciled differences (with the reason)

| Fork | Resolution |
|---|---|
| Pointer-only claim vs typed-payload claim | **Pointer-only claims** (DefectClaim → normativeRef + observationRefs + prose); the typed payload lives in an attested `observations[]` catalog, NOT duplicated in the claim. Reason: giving the agent the document doesn't make its interpretation authoritative; duplicated normative/observation copies drift and there's no oracle to check them against in production. |
| Ambiguity: unscored vs first-class scored | **Both** — scored on its OWN track in gold eval (ambiguityLocusRecall/Precision, reading-level recall/precision) but NEVER enters defect recall/coverage/site verdict. A defect claim at a confirmed ambiguous locus = `JUDGMENT_WITHHELD_AMBIGUOUS`. GPT superseded its earlier "report-only" position — we must measure whether the extractor invents ambiguities. |
| Boolean conjunction vs typed-agreement+verifier | **Boolean conjunction with tri-state predicate verification** (verified / contradicted / insufficient). A model verifier produces an atomic decision + evidence refs, never a similarity score, and can't override structural contradiction or fill missing evidence. Image-only evidence needs deterministic OCR/vision or panel certification, else inconclusive. |
| `itemRefs → affectedObligationIds` match precondition | **DROPPED** — it imported the broken lexical obligation matcher into defect scoring. Scorecard now reports `defectCorrect` / `contractLinked` / `contractGapDiscovered` / `orphanedClaim` independently, so an agent can earn defect credit while still losing extraction fidelity for missing the obligation. |
| Mechanical derivation from JSON patches | Patches give **mutation provenance, not authoritative behavior**. Three layers: `mutationFact` (structural change) + `behavioralOracle` (independently executed) + `manifestations[]` (typed observable templates). Every scoreable defect needs ≥1 validated manifestation; unobservable mutations are quarantined; incidental (unseeded) defects are scoreable once confirmed. |
| Claim-kind granularity | **10 observable defect types** (GPT's smaller algebra + Fable-agent's field-role tables). Diagnostic categories (wrong-skip-target, off-by-one, wrong-calc-source) become scorer-derived ANNOTATIONS, not agent-declared kinds. |
| `checked[]` ledger | **Not added** — `observations[]` + per-facet results already record it; a second ledger can disagree. |

## 3. Resolutions to the new problems (neither draft covered these)

- **A1 — missing global/cross-cutting obligations (the extraction's biggest real failure):** add a `ScopedRequirement` form (scope + quantifier + selector + exceptions + facet). "Every question is compulsory" is extracted ONCE as a survey-scoped requirement; a deterministic expander materializes one floor case per applicable question. Extraction scores the scoped rule once; execution must exercise every materialized case; an obligation isn't "exercised" until all its floor cases have valid observations. Fixes both errors: one probe can't certify 11 questions, and the extractor isn't asked to restate the global sentence 11 times.
- **A2 — table/composite citations (verbatim-substring breaks on real docs):** replace the single quote with a document-hash-bound **source-atom graph** (blockId + kind + table coordinates + role + atomTextHash, plus a `composition` declaring how fragments combine). Each fragment verifies exactly against its atom; the human `displayQuote` stitches fragments but carries zero identity weight. A malformed citation to a correct fact = `PROVENANCE_INCOMPLETE`, not an invention.
- **A3 — invented obligations:** confirmed inventions cost extraction precision. BUT (changed by the blind-corpus evidence) a well-typed, **source-verified** unmatched requirement is `oracle-gap-candidate` = neutral-but-BLOCKING pending adjudication, not an immediate FP; confirmation versions the oracle + rescores, rejection converts to FP. Unsupported inventions remain immediate FPs.
- **B — oracle over-assertion:** every normative field carries `assertionStatus` (entailed / explicit-negative / document-silent / ambiguous / disputed) + adjudication provenance. Only `entailed` and `explicit-negative` constrain matching; `document-silent` is outside the predicate (NOT an agent wildcard); `disputed` leaves the denominator until reconciled. Gold encodes the MINIMUM proposition the document entails (e.g. "error shown" scores; "message names the question" is document-silent → a generic error passes). No "oracle may be wrong" confidence discount — disputed facts simply can't enter the scoring oracle.
- **C — path-dependent behavior (from the two-tier coverage ruling):** NOT a new claim kind. Per-observation verdicts + deterministic aggregation: per obligation, FAIL if any floor or executed exploration case fails; later passes never erase a fail; `pathConsistency: mixed` + a `divergenceSet` when routes disagree. `testComplete` requires floor completion AND completion of the finite pinned exploration plan — so a run can be N/N obligation coverage yet `testComplete: false`.

## 4. Merged claim-kind registry (10 defect kinds + 2 non-defect tracks)

`rendered-state-mismatch` (question/instruction/option/label/copy/control presence+content — absence needs complete scoped inventory) · `visibility-mismatch` (question/section shown-state vs typed condition) · `routing-mismatch` (trigger agrees, destination differs) · `condition-mismatch` (trigger set differs) · `validation-mismatch` (under/over-enforcement, exact probe input+result) · `piping-mismatch` · `carry-forward-mismatch` (complete source+target collections) · `calculation-mismatch` (discriminating input vector) · `loop-mismatch` · `ordering-mismatch` (fixed/randomized/anchor; randomization failure needs repeat evidence). Non-defect: `ambiguity` (≥2 typed readings, site judgment withheld), `taxonomy-gap` (neutral, capped, blocks final score pending adjudication). Registry precedence resolves duplicate symptoms (visibility → condition → routing → ordering → rendered-state; root-cause annotations never create extra TPs).

## 5. Schema deltas (2.0.0, breaking)
RunRecord adds: `contract.requirements[]` (scoped, typed facets, epistemic states, source-atom refs, testability) · `contract.facetInstances[]` (materialized floorCases + expansion certificates) · `contractSupplements[]` (non-denominator) · `observations[]` (attested, typed, completeness, verifier decision) · `claims[]` (claimClass/claimType/normativeRef/observationRefs/prose) · separate `ambiguities[]`/`taxonomyGaps[]`/`blockers[]` · `itemResults[].facetResults[]` (case statuses, aggregate verdict, pathConsistency, divergenceSet) · `exploration` (plan hash + per-kind counts) · projection/normalizer versions. Removes: scored expected/observed, agent documentSays/siteShows, document-live-disagreement, checked[], stitched-quote authority, agent-recomputed fields, the itemRefs precondition. OracleRecord adds documentRequirements[] (assertion states + adjudication), facetInstances/floorCases, route classes, defects[] (origin seeded|incidental + manifestations), ambiguityLoci[], oracleQuarantine[], golden snapshots. Scorecard separates identification / fidelity / provenance / floor coverage / exploration completion / defect P+R / ambiguity P+R / oracle-gap / path-consistency / seeded-vs-incidental.

## 7. Residual risk + the one owner fork
Does NOT prove: extraction found every requirement; the oracle is complete + minimally entailed; a "complete" DOM/vision observation is semantically correct; the finite exploration model covers an exponential state space; black-box evidence identifies internal cause; vendor anti-bot/virtualization/session-loss permit complete observations; ambiguity adjudication reaches acceptable reviewer agreement; a malicious agent can't flood oracle-gap candidates to force adjudication (caps + provisional-blocking mitigate, don't eliminate).

**Single biggest P1 risk:** extraction completeness + gold fidelity for global, cross-cutting, table-derived requirements — an exact typed matcher faithfully enforces an incomplete or over-assertive contract, and the blind extraction already showed both directions.

**OPEN OWNER FORK (GPT changed its own default on the blind-corpus evidence):** an oracle-unmatched but well-typed, source-verified requirement — is it **(a) neutral-but-blocking pending adjudication** [GPT's new recommendation; strict-immediate-FP judged unsafe now that real oracle omissions are proven] or **(b) strict oracle-gap-as-FP** [the original stance]? Unsupported inventions are immediate FPs either way. This must be an explicit owner decision, not buried in scorer code.

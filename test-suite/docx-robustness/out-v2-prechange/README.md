# `out-v2-prechange/` — DO NOT DELETE, AND DO NOT REGENERATE

These 20 `.txt` files are `annotate(parseDocxBlocks(bytes).blocks)` for every document in
`../corpus/`, captured from **`worker-v2/src/extract/docx-blocks.ts` as it stood at git HEAD
before the merged-cell / dropdown / unicode work** (the parser that scored 87/99).

They are not output. They are a **fixture**, and one test depends on them:

> `worker-v2/tools/tests/docx-robustness.test.mjs` →
> *"THE COLLATERAL PROFILE: only 03, 08, 11 and 16 read differently from the pre-change parser"*

That test re-extracts the whole corpus and asserts the set of documents whose text changed is
exactly `{03, 08, 11, 16}` — the four the fixes are about. It is the only check in the tree that
would notice a parser change that ALSO quietly moved an unrelated document. Nothing else looks
at a document the probes happen not to cover.

**Regenerating these from the current parser would make that test assert `[] === []` and pass
forever** — a check over an empty denominator, which is a failure mode this repository has
shipped before. If a future change is *intended* to alter more documents, change the expected
list in the test and say why in the same commit; do not refresh the captures to match.

Reproduce (read-only, from the repo root):

```sh
git show <pre-change-rev>:worker-v2/src/extract/docx-blocks.ts > /tmp/docx-blocks.ts
# bundle it with esbuild, run annotate(parseDocxBlocks(bytes).blocks) over ../corpus/*
```

Current live output lives in `../out-v2/` and is regenerated by `node run-harness-v2.mjs`.
